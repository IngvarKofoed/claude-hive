# Ship lane: Land on main squashes, tests and pushes one commit

A card in Ship now lands with one button. Land on main is your approval. The hive then squashes the card onto the
latest main as one commit, in the repo's own commit style, runs the setup's tests on it, and pushes it without force.
It updates your checkout's main only when that's safe, removes the card's worktree and branch, and moves the card to
Done. With an `origin`, the whole hive now works from a fetched `origin/main`. Built to `docs/specs/2026-11-27-ship-lane.md`.

## Detail
- **Approve first, then do it all,** instead of the docs' prepare-then-approve. You chose one button, so you don't see
  the commit or the test result before pressing. Anything that goes wrong stops the landing before main changes.
- **The squash touches no working folder:** `git merge-tree --write-tree` finds the merged tree, or the conflicting
  files, and `git commit-tree` makes the commit. Rejected `git merge --squash` in the worktree, which leaves a
  half-done merge to abort. `commit-tree` runs no commit hooks; your `pre-push` hook does run.
- **One base for the whole hive** (revises "only the local main is merged; fetching is Ship's business" from
  `2026-11-26-build-lane-developer`). With an `origin`, worktrees branch from a freshly fetched `origin/main`,
  Build merges it, and Ship squashes onto it.
  - Rejected one base per lane: a conflict at Ship could bounce between Build and Ship with nothing to resolve, and
    unpushed local commits would land under the card's message.
  - Ship refuses while your local main has commits that `origin` lacks.
  - A failed fetch falls back to the last fetched `origin/main` in Refine and Build, but stops a landing.
- **Main moves forward only:**
  - A push refused because main moved squashes and tests again, up to 3 times. Any other push or fetch failure
    stops the landing with git's output and Retry.
  - Your checkout's main moves by compare-and-swap when main isn't checked out. When it is checked out, it moves with
    `merge --ff-only`, and only while that checkout is clean. Otherwise Done says it's behind. Without a remote, the
    landing waits for a clean checkout.
- **The commit message:** a short `committer` session on Sonnet writes it from the spec, the diff stat and the last 15
  messages on main, so it matches the repo's style.
  - The hive appends `Spec:` and `Hive-Card:` itself.
  - A session that fails, reports nothing, or runs past 3 minutes falls back to a message from the card: its title
    and the first "What you get" bullet.
- **A conflict goes to Build** with the reason as the developer's text, and `Card.shipAfterCheck`. After Check, the
  card returns to Ship, not Try it, and waits for you to press Land on main again, since its code changed. The flag is
  cleared by any move to Try it or Spec.
- **A failing test keeps the card in Ship,** with the output, Retry and Back to Build. Rejected sending it straight
  back to Build, which a flaky test would turn into a trip through Build and Check.
- **Uncommitted work in the card's worktree blocks Land on main.** "Discard them and land" runs `git reset`, `git checkout -- .`
  and `git clean -fd`, which keep git-ignored files such as `.env`, so the tests run on exactly what lands.
- **Known, permanent gap:** deleting `hive/<card>` makes its checkpoint commits unreachable, so cards landed before
  the history slice have no per-lane history. You chose that over keeping them under a `refs/hive/landed/` ref.
- **A landing survives a restart:** `Card.landing` is stored before the push.
  - At startup, a commit already on main finishes the landing.
  - Anything else puts the worktree back on its branch, with "Nothing reached main" and Retry.
  - If `origin` can't be reached, the hive makes no claim either way.
- **A failed Prepare it again keeps the setup that worked,** with its start and test commands, and a note saying so.
  Known gap: the earlier setup is kept in memory only. A hive restart during Prepare it again ends it as failed, and
  the setup that worked is lost.
  This was the open question from `2026-11-27-try-it-runs-the-app`.
- **`Project.runCommand` and `Project.testCommand` are gone from the data model.** Each card's setup decides them.
- **A landed card shows no badge** on the board or its page. It needs nothing from you.
- **Verified end to end** on the scratch web app, with a bare repo as its `origin`:
  - Land on main squashed the card onto `origin/main` and ran `npm test` on it.
  - A real Sonnet committer wrote a subject and body explaining the change. The hive added `Hive-Card:`; there was
    no `Spec:`, because this scratch card never went through Spec.
  - It pushed one commit directly on top of the previous main, with no merge.
  - It fast-forwarded the clean checkout's main, removed the worktree and branch, freed the ports, and Done showed
    the commit. The console was clean.
- **Not covered by that run:** the fake-runner and bare-origin tests cover these.
  - a conflict, a failing test, a refused push, unpushed local commits, a dirty checkout with and without a remote;
  - the committer's fallback;
  - restart recovery;
  - your magic-grow card, which wasn't landed.
